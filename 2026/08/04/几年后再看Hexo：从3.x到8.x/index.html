几年后再看Hexo：从3.x到8.x

发表于 2026-08-04 更新于 2026-08-04

本站页脚还写着 Hexo 3.9.0 + NexT.Pisces 7.3.0。若你上次认真用 Hexo 也是那一代，下面这份速览够用来接上进度。

一句话结论

Hexo 仍然是「Markdown 写博客 → Node.js 生成静态站 → 一键部署 GitHub Pages」这条路。最新稳定版是 8.1.2（2026 年 5 月），核心配方没变，变的是 Node 门槛、性能、插件边界，以及主题生态。

版本时间线

  • 3.x（你可能熟悉的年代）：Swig/Nunjucks 标签语法、插件生态成型；本站生成器就是这一代。
  • 4.x：内置 Swig 渲染器拆出，主题更多依赖独立 renderer；开始更积极跟进 Node LTS。
  • 5.x（2020）：性能大跃；内置 Prism；新增 Injector；主题配置与站点配置分离；去掉全局 lodash。
  • 6.x（2021）：主题 package.json 也可声明插件；默认更安全地转义部分输出。
  • 7.x（2023）：gist / youtube / jsfiddle / vimeo 内置标签迁到 hexo-tag-embed；高亮统一走 syntax_highlighter 配置。
  • 8.x（2025）：弃用 Node 16/18，要求 Node.js ≥ 20.19；继续做外链处理、归档、标签解析等性能优化。当前最新 8.1.2。

什么几乎没变

hexo init → hexo new → hexo s / hexo g → hexo d 这一套还在。Markdown、front-matter、hexo-deployer-git、主题 + 插件扩展，仍然是主力玩法。

主题与生态

NexT 已演进到 8.x（例如 8.27.0），并要求 Hexo ≥ 7。本站还停在 NexT 7.3，和 Hexo 3.9 产物是匹配的；若重建源工程，建议直接上 Hexo 8 + 新版 NexT，而不是在 3.x 上硬续。

静态站点赛道里 Hugo、Astro、Eleventy 更常被拿来比速度或前端集成；Hexo 的优势仍是 Node 栈友好、中文社区资料多、个人博客心智成本低。

和本站的关系

仓库里目前只有生成后的静态 HTML。短期可以继续手写页面更新；想长期用上 8.x 的能力，还是要找回（或重建）Hexo 源工程，再 hexo generate 覆盖 public。
